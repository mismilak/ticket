# سامانه فروش بلیط (Django) — قابل شخصی‌سازی و فروش به مشتری

سایت بلیط‌فروشی شبیه ملوتیک: رویدادهای **چندسانسه**، **فروش بر اساس صندلی** (با **قیمت متفاوت برای هر صندلی**) و **فروش تعدادی**، سالن **چندطبقه** (همکف، بالکن، ...)، ورود با پیامک کاوه‌نگار، درگاه‌های ملت / سامان کیش / زرین‌پال و پنل مدیریت کامل.

سمت سرور با **Django 5** نوشته شده. همه فایل‌های فرانت (بوت‌استرپ RTL، آیکن‌ها، وزیرمتن، QR) لوکال در `static/vendor` هستند و CDN لازم نیست.
> نسخه قبلی (Laravel/PHP) در تاریخچه git (کامیت `270f2958`) موجود است.

## نصب و اجرا

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env            # DJANGO_SECRET_KEY و ALLOWED_HOSTS را حتماً تنظیم کنید
python manage.py migrate
python manage.py bootstrap_site # مدیر اولیه + دسته‌بندی‌ها + صفحات ثابت
python manage.py seed_demo      # (اختیاری) داده نمونه: سالن دو طبقه، رویداد سه‌سانسه، قیمت اختصاصی صندلی
python manage.py runserver
```

- مدیر پیش‌فرض: موبایل `09120000000`، رمز `admin1234` (با `ADMIN_MOBILE` / `ADMIN_PASSWORD` در `.env` یا آرگومان `--mobile/--password`). ورود مدیر: `/panel/login/` — **رمز را عوض کنید** (پنل ← کاربران). مدیر با OTP هم وارد می‌شود.
- با `DJANGO_DEBUG=1` و نبودن کلید کاوه‌نگار، کد OTP روی صفحه نمایش داده می‌شود (فقط توسعه).
- **Production:** `DJANGO_DEBUG=0`، `python manage.py collectstatic --noinput`، اجرا با `gunicorn config.wsgi` پشت Nginx/Apache. استاتیک‌ها با WhiteNoise سرو می‌شوند. پوشه `media/` (تصاویر آپلودی) را وب‌سرور سرو کند و `SERVE_MEDIA=0` بگذارید (یا برای سایت کوچک همان `1` بماند). با HTTPS: `DJANGO_HTTPS=1` و `DJANGO_CSRF_TRUSTED_ORIGINS`.
- MySQL: `pip install mysqlclient` و `DB_ENGINE=mysql` + `DB_*` در `.env`.
- بکاپ: فایل `db.sqlite3` (یا دیتابیس MySQL) و پوشه `media/`.

## پنل مدیریت (`/panel/`)

| بخش | توضیح |
|---|---|
| **تنظیمات** | نام، لوگو، فاوآیکن، رنگ‌ها، CSS/کد `<head>` دلخواه، فوتر و شبکه‌های اجتماعی، مهلت پرداخت، کارمزد، کاوه‌نگار، درگاه‌ها |
| **مجوزهای فوتر** | اینماد/ساماندهی و ...: آپلود تصویر + لینک یا کد HTML نماد |
| **صفحات / اسلایدر / دسته‌بندی‌ها** | محتوای سایت |
| **سالن‌ها و پلان صندلی** | طراح بصری چندطبقه: ردیف (با انحنا)، انتخاب و جابجایی گروهی، دسته‌بندی رنگی، صحنه/متن/مستطیل، Undo |
| **رویدادها** | چند سانس، تاریخ شمسی، قیمت پایه هر دسته صندلی، بلیط عمومی با ظرفیت، گزارش فروش |
| **قیمت‌گذاری صندلی‌ها** | روی نقشه صندلی‌ها یا ردیف را انتخاب (کشیدن جعبه‌ای) و قیمت اختصاصی بدهید؛ قیمت اختصاصی بر قیمت پایه دسته غلبه می‌کند و حتی صندلی بدون قیمت پایه را قابل فروش می‌کند |
| **سفارش‌ها / کنترل بلیط / کاربران** | جزئیات تراکنش، لغو، ثبت ورود با کد، نقش‌ها |

## قواعد فروش
- هر **سانس** موجودی صندلی و ظرفیت مستقل دارد.
- قیمت هر صندلی = قیمت اختصاصی همان رویداد (اگر باشد) وگرنه قیمت پایه دسته‌اش.
- رزرو موقت (`hold_minutes`) و جلوگیری از فروش مضاعف با ایندکس یکتا روی `OrderItem.lock_key` (`سانس:صندلی`)؛ حتی با درخواست‌های همزمان.

## درگاه‌ها و پیامک
تنظیم از پنل ← تنظیمات. زرین‌پال (v4 + Sandbox)، بانک ملت (به‌پرداخت، SOAP)، سامان کیش (SEP/OnlinePG)، درگاه آزمایشی داخلی (فقط تست؛ در سایت واقعی خاموش)، کاوه‌نگار (`verify/lookup`). آدرس بازگشت هر تراکنش خودکار ساخته می‌شود: `/payment/callback/<id>/`.

> ⚠️ اتصال به بانک‌ها/زرین‌پال/کاوه‌نگار بر اساس مستندات عمومی نوشته شده و در محیط توسعه امکان تست واقعی نبود. جریان کامل خرید با درگاه آزمایشی و تست‌های خودکار (`python manage.py test`) بررسی شده است. قبل از انتشار یک پرداخت واقعی کم‌مبلغ با هر درگاه امتحان کنید.
